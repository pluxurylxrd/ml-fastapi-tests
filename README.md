# API для модели анализа тональности

REST API для модели определения
тональности отзывов покупателей маркетплейса, разработанной
в рамках части 1 (репозиторий ml-tasks, задача 1)

## Задача

Предоставить доступ к модели машинного обучения по HTTP, чтобы
её могли использовать внешние потребители (мобильное приложение,
панель модерации, аналитика) без установки Python, зависимостей
и загрузки весов модели

## Модель

cointegrated/rubert-tiny-sentiment-balanced - BERT для русского языка,
дообученный на классификацию тональности: negative / neutral / positive.
Обоснование выбора и метрики качества приведены в репозитории ml-tasks,
задача 1

## API

### POST /predict

Запрос:

{
  "text": "Заказ пришёл быстро, качество отличное"
}

Ответ, код 200:

{
  "label": "positive",
  "score": 0.9832,
  "probabilities": {
    "negative": 0.0018,
    "neutral": 0.015,
    "positive": 0.9832
  }
}

Ограничения поля text: от 1 до 5000 символов, тип - строка.
При нарушении возвращается код 422 с описанием ошибки

Интерактивная документация доступна по адресу /docs,
схема OpenAPI - по адресу /openapi.json. Обе генерируются
автоматически из описаний моделей Pydantic

## Технические решения

### Загрузка модели при старте приложения

Модель загружается один раз в обработчике lifespan, до приёма первого
запроса, и переиспользуется всеми последующими вызовами

Основание: замеры в части 1 показали, что загрузка модели занимает
около 1.5 с, а одно предсказание - около 10 мс. Загрузка модели внутри обработчика запроса
означала бы задержку в 1.5 с для каждого клиента

### Валидация данных через Pydantic

Схемы ReviewRequest и SentimentResponse описывают структуру запроса
и ответа декларативно. Проверка типов, обязательности полей и границ
длины выполняется фреймворком до вызова обработчика, код валидации
не пишется вручную

Схема ответа дополнительно гарантирует, что обработчик возвращает
данные ожидаемой структуры: нарушение контракта обнаруживается
на стороне сервиса, а не у потребителя API

### Обработка ошибок

Пустая строка и превышение длины отсекаются ограничениями Pydantic.
Строка из одних пробелов проходит проверку длины, но отклоняется
функцией predict, исключение ValueError перехватывается
и преобразуется в ответ 422 вместо 500. Разграничение существенно:
код 5xx означает отказ сервиса, 4xx — некорректный запрос клиента

### Состав зависимостей

В requirements.txt включены только библиотеки, необходимые для работы
API: веб-фреймворк, сервер, модель и средства тестирования

## Тестирование

Используется pytest и TestClient из состава FastAPI. TestClient
выполняет запросы напрямую к приложению в памяти, без запуска
сетевого сервера и занятия порта

Клиент создаётся фикстурой с областью видимости module: модель
загружается один раз на весь набор тестов, а не на каждый тест.
Создание клиента внутри блока with обязательно, именно это
инициирует событие запуска приложения и загрузку модели

Реализовано 10 тестов:

Содержательные:
- распознавание положительного отзыва
- распознавание отрицательного отзыва

Контракт ответа:
- состав полей ответа и допустимые значения label
- сумма вероятностей по трём классам равна единице
  (сравнение с допуском 0.01 ввиду округления до 4 знаков)

Отклонение некорректных запросов (ожидается код 422):
- пустая строка
- строка из пробельных символов
- отсутствие обязательного поля
- значение неверного типа
- превышение максимальной длины

Маршрутизация:
- обращение к несуществующему адресу возвращает 404

Нейтральный класс намеренно не проверяется на точное значение метки:
анализ в части 1 показал, что нейтральные отзывы модель систематически
относит к соседним классам, и такой тест был бы нестабильным

Запуск: pytest -v
Результат: 10 passed

## Автоматический запуск тестов

Настроен workflow GitHub Actions (.github/workflows/tests.yml),
запускающийся при каждом push и при создании pull request

Этапы: получение кода, установка Python 3.11, установка зависимостей
из requirements.txt, запуск pytest. Каждый прогон выполняется
на чистой виртуальной машине Ubuntu, поэтому полнота requirements.txt
проверяется автоматически: отсутствие любой зависимости приводит
к падению сборки

Кэширование загруженных пакетов и весов модели не применяется -
время прогона составляет около двух минут

## Запуск

pip install -r requirements.txt
uvicorn main:app --reload

Документация: http://127.0.0.1:8000/docs

Тесты:

pytest -v
